# v0.0.6

## Codex completion metadata

Codex rollout `CommandExecution` and `FileChange` completion records can now be retained as bounded,
typed timeline artifacts. The mapping follows the core rollout schema from Codex 0.166.0, rather than
assuming the app-server schema has the same shape.

The new artifacts record selected metadata: native item ID, status, valid exit code when present,
command arguments and working directory, or changed paths and change types. Missing, malformed or
oversized fields are marked unavailable. Command output, file contents, diffs and private reasoning
are not stored in these new artifacts. Existing credential-pattern filtering still applies; it cannot
recognize every possible secret in command arguments or paths.

Existing response-item capture, offset identities, acknowledged cursor advancement and pending-upload
replay remain unchanged. All five host packages carry the same shared runtime.

## Limits

- These are metadata artifacts, not canonical command, owned-edit or pull-request records. This release
  alone does not repair Git-panel associations or prove that a particular pull request was captured.
- Already-consumed transcript records are not backfilled. Capture remains bounded and does not promise
  complete history or semantic deduplication across native and response-item records.
- Native installation, authentication and hook approval remain separate checks. The existing Node 22
  CI configuration covers Linux, macOS and Windows; it does not certify every native host on every OS.
- Grok and Cursor transcript dialect verification limits remain unchanged. See [Host support](../SUPPORT.md).

## Distribution

The package version and generated host manifests are 0.0.6. External Node.js 22+ and an Estelle account
key remain required. The [installation guides](../install/) retain the existing host-specific setup.
Kimi's bare GitHub install selects the latest published release; a branch update or version change
alone is not a published release.
